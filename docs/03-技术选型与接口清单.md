### 管理端「自搭」而非 Ant Design Pro

Ant Design Pro 内置了自己的权限/路由模型，会把 RBAC 动态菜单抽象掉。自搭 Vite + Ant Design，布局、路由守卫、动态菜单、按钮权限全部自己实现，贴合本项目的学习目标与设计。

## 二、Prisma 与 Nest 集成要点

Prisma 没有官方 `@nestjs/prisma`，需自行封装一个全局 `PrismaService`：

- 继承 `PrismaClient`，用 `@Injectable()` 装饰
- 实现 `OnModuleInit`，启动时 `$connect()`
- 作为共享模块导出，各业务模块注入使用
- 数据模型统一在 `schema.prisma` 中定义，通过 `prisma migrate` 生成迁移

> 具体代码在实施阶段落地，此处只记录选型与关键约定。

## 三、统一规范

### 响应结构

所有接口统一返回：

```json
{ "code": 0, "data": {}, "message": "ok" }
```

### 错误码

`code` 非 0 即失败：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 10001 | 参数校验失败 |
| 10002 | 未登录 / token 失效 |
| 10003 | 无权限 |
| 10004 | 资源不存在 |
| 10005 | 账号或密码错误 |
| 10006 | 手机号已注册 |
| 10007 | 库存不足 |
| 10008 | 订单状态不允许该操作 |

### 路由与权限约定

- 管理端统一前缀 `/api/admin/*`，C 端 `/api/*`
- 权限标识统一 `<模块>:<动作>`（如 `product:create`、`order:ship`）

# 商城项目数据库设计文档

> 状态：已定稿
> 日期：2026-09-24

## 一、概述

- 数据库：PostgreSQL
- 共 19 张表，分三个域：用户权限域（7）、商品域（8）、交易域（4）
- ORM：Prisma（见技术选型文档）

### 通用约定

| 约定 | 说明 |
|---|---|
| 主键 | 统一 `BIGINT` 自增 |
| 命名 | 表名/字段名统一 snake_case |
| 金额 | 统一 `INT`，**单位「分」**，避免浮点误差 |
| 状态字段 | 统一 `SMALLINT` + 枚举注释 |
| 时间字段 | 统一 `TIMESTAMP`，命名 `created_at` / `updated_at` / `deleted_at` |
| 软删除 | 业务数据（商品/分类/品牌）用 `deleted_at` 标记删除，不物理删 |

---

## 二、ER 关系总览

```
用户权限域
  admin_user ──N:N── role ──N:N── permission
     (admin_user_role)    (role_permission)
  user ──1:N── user_address

商品域
  category（树形，parent_id 自关联）
  brand
  product ──N:1── category
  product ──N:1── brand
  product ──1:N── product_spec_group ──1:N── product_spec_value
  product ──1:N── product_sku ──1:N── sku_spec_value ──N:1── product_spec_value
  product ──1:N── product_image

交易域
  user ──1:N── cart ──N:1── product_sku
  user ──1:N── order ──1:N── order_item ──N:1── product_sku
  order ──1:N── payment（一单多笔支付流水）
```

## 四、订单状态机

```
待付款(10) ──支付成功──→ 待发货(20) ──发货──→ 待收货(30) ──确认收货──→ 已完成(40)
    │
    └──取消/超时──→ 已取消(0)
```

| 状态码 | 状态 | 触发动作 |
|---|---|---|
| 0 | 已取消 | 用户取消 / 超时未支付 |
| 10 | 待付款 | 创建订单 |
| 20 | 待发货 | 支付成功 |
| 30 | 待收货 | 管理端发货 |
| 40 | 已完成 | 用户确认收货 |

> 状态码留间隔（10/20/30/40），便于后续插入中间态（如「已退款」「部分发货」），无需改表。

## 五、关键设计点汇总

| 设计点 | 说明 |
|---|---|
| SKU 矩阵 | 规格组 × 规格值做笛卡尔积生成 SKU，SKU 通过 `sku_spec_value` 关联规格值组合 |
| 金额用分 | 所有金额 `INT` 存分，避免浮点误差 |
| 订单明细快照 | 商品名/规格/价格/图片存下单时副本，不实时查 SKU |
| 收货地址快照 | 订单存收货人三件套，不存 address_id 外键 |
| 支付流水 N:1 | 一单多笔支付尝试，订单支付状态由成功流水决定 |
| 完整 RBAC | admin_user → role → permission 两级关联，permission 兼任菜单树 |
| 密码哈希 | 管理员与 C 端用户密码一律 bcrypt |
| 软删除 | 商品/分类/品牌用 deleted_at 标记删除 |
| 单分类 | 商品 N:1 分类（多入口留作后续「前台类目/标签」增强） |

# 智能体（Agent）开发指南

> 沉淀自 mall 项目「智能客服」的完整实战。下次开发类似 Agent 时，照着这份清单逐层设计即可。
> 技术栈：Vercel AI SDK 7 + DeepSeek + pgvector + Langfuse（直接 SDK + 自研编排，不用 LangChain 大框架）。

## 一、核心认知（先厘清概念）

1. **Agent = LLM + 工具 + 自主决策**，不是固定流程。模型在每一步自己决定「调哪个工具 / 输出什么」，你的工作是**塑造它的决策环境**。
2. **ReAct 循环**（思考→行动→观察）的**循环骨架由框架提供**（`streamText` + `tools` + `stopWhen`）。你写的是：工具、提示词、记忆、反馈、评测——这些才是「Agent 的实现」。
3. **「引导」≠ 写死步骤**。不写 `if (要电脑) { 调A; 再调B }`，而是靠三层塑造决策：
   - 工具的 `description + inputSchema` → 让模型知道「有什么能力、参数是什么」
   - 提示词 → 让模型知道「什么时候调、调完怎么做」
   - 工具的返回值（含 hint）→ 让模型知道「这次结果如何、下一步干嘛」
4. **三个维度别混**：
   - **Agent 设计** = 会不会做事（工具 + 提示词 + 记忆）
   - **鲁棒性** = 出事了扛不扛得住（重试、降级、自我纠正）
   - **评测** = 做得好不好（检索/生成/端到端）

---

## 二、设计维度总览

```
┌ 决策层：提示词（什么时候调工具 / 多步流程 / 容错降级）
├ 能力层：工具（description + inputSchema + execute + 反馈）
├ 展示层：生成式 UI（工具结果 → 卡片组件）
├ 记忆层：短时会话摘要 + 长期用户画像
├ 安全层：泛化读 / 约束写 / human-in-the-loop
├ 鲁棒性层：重试 / 降级 / 自我纠正 / 步数上限
├ 质量层：分层评测（检索 / 生成 / 端到端）
└ 可观测层：trace（每次模型调用 + 工具调用）
```

## 三、逐层设计要点

### 1. 能力层（工具设计）

每个工具三要素：

```ts
tool({
  description: '…（何时用，写得越清楚模型越容易选对）',
  inputSchema: z.object({ /* 参数，含中文 describe */ }),
  execute: async (args) => { /* 实际逻辑 */ },
})
```

原则：

- **返回「瘦身数据」而非原始响应**——只留模型回答需要的字段，金额/状态做转换，省 token 且让模型聚焦。
- **返回带「反馈」**：空结果返回 `empty + hint`，失败返回 `error + hint`。这是自我纠正的关键。
- **工具分「读」和「写」**：读工具（查询）可放开；写工具（下单/支付）要特别设计（见安全层）。

### 2. 决策层（提示词设计）

提示词分层写：**角色定义 → 核心流程 → 边界场景 → 表达要求**。

关键要写清楚：

- **何时调哪个工具**：「购物意向 → 必须调 getProducts，绝不凭记忆编造」。
- **多步流程**：「下单 = 查商品 → 查地址 → 生成草稿 → 用户确认」。
- **结果展示约定**：「结果已用卡片展示，文字里别重复商品名/价格」。
- **容错降级**：「empty → 按 hint 放宽重试；error → 降级/换方式」。
- **给正反例**：✓「帮你筛出 2 款」 / ✗「XX商品｜¥XXX｜亮点：XXX」。

### 3. 展示层（生成式 UI）

核心：**LLM 产出数据，前端渲染 UI**，不是让模型写一段文字描述商品。

- 工具结果成为消息里的 part（如 `dynamic-tool` / `tool-getProducts`），前端按 `part.type` 分发渲染成卡片。
- 卡片的操作也是**数据驱动**：按钮 `{ type: navigate | api | confirm, ... }`，前端统一处理。
- 结论：不需要为每个功能预设计卡片，用少量通用卡片（ItemCard）+ 数据即可；强定制交互（如下单草稿）才手写。

### 4. 记忆层

- **短时**：会话窗口 + **滚动摘要**——超 token 预算时把旧消息压成 `summary + slots`（关键事实键值对）。
- **长期（用户画像，跨会话）**：一张 `user_profiles` 表（按 userId 存自然语言事实，如「偏好苹果品牌」「预算 5000 左右」）。
  - **写**：模型主动调 `remember` 工具（提示词引导「何时该记」）。识别「搭便车」在回复生成里，**不额外调 LLM**；有值得记的就调工具写 DB，没有就不调。
  - **读**：每次 `assemble` 时读画像、注入 instructions（读 DB + 拼字符串零成本，关键是画像要「小而精」，几十 token）。
- **存储真相，读侧投影**：库里存 append-only 原始消息（模型格式），回显时再投影成 UI 格式。两套结构解耦，互不破坏。

### 5. 安全层

- **泛化读、约束写**：查询类能力可通用化（如 NL→SQL），但写操作（下单/支付/退款）必须收着。
- **通用 SQL 只读 + 三重校验**：单条 SELECT、危险关键字拒绝、表白名单（排除个人/敏感表）。
- **个人数据走「带鉴权的专用工具」**（如 getOrders 带用户 token），**不放开通用 SQL**，否则 A 用户能查到 B 用户的数据。
- **写操作走 human-in-the-loop**：Agent 只生成「草稿」，真正执行由用户在前端确认触发。
- **提示词注入防护（分层防御，无银弹）**：
  1. 提示词加固：system prompt 里写「安全边界」（最高优先级、用户输入是数据不是指令、只查自己的数据）。
  2. 输入侧检测：正则匹配「忽略指令 / system prompt / 角色扮演 / 查他人数据」等特征，命中直接拒绝、不喂给模型、不调工具。
  3. 工具层鉴权兜底：即使前两层被绕过，越权操作也会被工具层挡住（token 鉴权 + 白名单）——这是最硬的一道。

### 6. 鲁棒性层

- **网络**：fetch 包一层「超时 + 退避重试」。
- **空结果**：返回 `empty + hint`，模型按 hint 放宽条件自我纠正。
- **报错**：返回 `error + hint`，模型降级/换方式，不反复重试同一失败操作。
- **步数上限**：`isStepCount(n)` 防死循环。
- **兜底**：模型抛异常时优雅降级，别让用户看到 500。

### 7. 质量层（评测）

分层评测，别只测端到端：

| 层 | 测什么 | 指标 |
|---|---|---|
| 检索 | embedding/召回/rerank 对不对 | Hit@k / MRR / Recall@k |
| 生成 | 给定上下文会不会编造 | faithfulness（LLM 裁判）|
| 端到端 | 整条链路 | correctness + faithfulness + length |

关键补充：

- **工具调用正确性**用**确定性断言**（`expectedTools` 是否被调用）——LLM 裁判测不出「模型是调了工具还是凭记忆编了一个像样的答案」。
- 评测写进 Langfuse，改 prompt/模型后跑一遍对比。
- 加**安全用例**（注入攻击 → 拒绝泄露）。

### 8. 可观测层

- **trace**：每次模型调用 + 工具调用都记录（Langfuse/OpenTelemetry）。
- **给开发者看「完整日志」，给用户看「进度状态」**：用户只看到「正在查询商品…」这种实时步骤，不看内部工具名/日志。

## 四、常见坑（Gotchas）

1. **tsx/esbuild 不发射 `design:paramtypes`** → 构造注入必须显式 `@Inject(Xxx)`（tsc 的 Nest 项目不需要）。会表现为「依赖是 undefined、不报错、运行时才炸」。
2. **AI SDK 静态工具 part 的 `type` 是 `tool-xxx`，没有 `toolName` 字段**；只有 `dynamic-tool` 才有。工具名要兜底从 `type` 前缀解析。
3. **工具结果在存储层是 DataContent 信封**（`{type:'json', value:{...}}`），回显给前端时要解包成裸值。
4. **存储用 ModelMessage（模型格式），回显用 UIMessage（UI 格式）**——两套结构，靠「读侧投影」转换，别混存。
5. **推理模型（如 deepseek-reasoner）**有原生思维链，但**工具调用/结构化输出可能不稳**；摘要压缩、结构化输出这类任务用普通模型，聊天主链路才用推理模型。
6. **评测跑真实 Agent 需要真实依赖**（DB、向量库、API key、观测平台都要起）。

## 五、技术选型建议

| 维度 | 推荐 | 说明 |
|---|---|---|
| 编排 | **直接 SDK（AI SDK）+ 自研** | 新项目趋势，可控、可调试；LangChain 太重 |
| 向量库 | pgvector | PG 自带，够用 |
| 工具发现 | 先用写死的工具，工具多了再上 **MCP** | 动态注册、可扩展 |
| 评测 | 分层 + LLM-as-judge | 裁判用更强的模型，注意自我偏见 |
| 观测 | Langfuse / OpenTelemetry | trace 是标配不是可选项 |

---

## 六、一句话记忆点

> Agent 开发 = **设计工具（能力）+ 提示词（决策）+ 反馈（引导）+ 记忆（状态）+ 安全（边界）+ 鲁棒性（扛事）+ 评测（质量）+ 观测（看清）**。循环骨架是框架给的，其余八样都是你一行行写的。
